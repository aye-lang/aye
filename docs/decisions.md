# Stage0 syntax and semantics decisions

Choices made in the stage0 compiler where the design doc did not fix the
answer. Each one can be revisited. The grammar is in `grammar.ebnf`.

## Syntax

- **Struct declaration:** `struct Name { field: T, ... }` at top level, with optional `pub`. Fields are separated by `,` or by newlines, and a trailing `,` is allowed.
- **`for` loop:** `for i in lo..hi { }` counts; the range is half-open. `lo` and `hi` must have the same integer type, and `hi` is evaluated once, before the first iteration. `i` is immutable. `in` is a contextual identifier, not a keyword, so the keyword count stayed at 28 (30 since `orelse` and `unreachable`, M9.5).
  - `for x in seq { }` and `for i, x in seq { }` walk an array or a slice (M6). `seq` is evaluated once, before the first iteration: a slice is copied (its pointer and length), and an array is read in place, so an assignment to a later element in the body is seen. `x` is an immutable copy of the element and `i` an immutable `usize`. A range `for` has one variable: `for i, x in 0..n` is an error. To change the elements, index: `for i, x in s { s[i] = x * 2 }`.
- **Ranges** (`..`) are not general expressions. They appear only in a `for` header and in slicing; `..=` only in a `match` pattern.
- **Slicing:** `a[lo..hi]`, `a[lo..]`, `a[..hi]` and `a[..]`.
- **Semicolons:** Go's insertion rule. A terminator is inserted after an identifier, a literal, `)`, `]`, `}`, `return`, `break` or `continue`. An explicit `;` is a lexical error.
  - `else` must be on the same line as the `}` before it.
  - A multi-line call, struct literal or array literal needs a trailing comma.
  - A binary operator that continues an expression must end the line.
- **Struct literals in headers:** `Name {` in an `if`, `while` or `for` header is parsed as the start of the body, as in Go. Put the literal in parentheses to use it there.
- **Comparisons do not chain.** `a < b < c` is a parse error.
- **`as`** binds looser than unary operators and tighter than `*`. So `-x as f32` means `(-x) as f32`, and `a * b as f32` means `a * (b as f32)`.
- **`defer`** takes a block or a simple statement (a call or an assignment). A deferred body cannot `return`, and it cannot `break` or `continue` out of itself.
- **`true` and `false`** are predeclared identifiers, not keywords. The parser reads them as literals.
- **Initializers:** `let` and `var` must always have one (`var x: T = v`). There is no zero-initialization yet.
- **Globals (M6):** a top-level `let NAME = value` is a constant, `var name = value` a global variable; `pub` makes either visible to other modules. Like a local `let`, an untyped integer literal gives `i64` (`let N = 4`); write `let N: usize = 4` for another type. Untyped constants, as in Go, would need a second kind of value that only constants have.
  - The value is computed when the program is compiled, as in Zig: literals, other `let` constants (of any module, in any order), operators, `as` casts, `.len` of an array, a field or element of a constant, and array, struct and enum literals. A call, a `var` global, a constant defined in terms of itself, and an operation that would panic at run time (overflow, division by zero, a shift out of range, a cast out of range) are E0089. So a global needs no initialization code and no initialization order.
  - The generated C is a static variable with a C initializer. An expression that reads a global copies it first, so a call later in the expression that changes a `var` global does not change the value already read.
  - A constant cannot be assigned or borrowed with `&mut` (E0032, with the fix-it `let` to `var`); `&CONST` is a `*T`. Locals cannot shadow globals, as for other top-level names.
- **Type aliases (M6):** a top-level `let Name = T` whose value names a type is an alias: `let NodePool = Pool(Node)`, `let Bytes = []u8`, `let P = *Node` (a value that does not read as an expression is parsed as a type, as for a `comptime` argument). It is decided by the value: a type name, a type function call or another alias makes an alias; it must be a `let` without a type annotation. An alias is the same type, not a new one, and works wherever its type does: in types, struct literals (`NodePool { ... }`), static calls (`NodePool.init(...)`) and enum values (`C.Red` after `let C = Color`).
- **Array literals** state their length, `[3]i32{1, 2, 3}`, or (M9.5) take it from the elements, `[_]i32{1, 2, 3}`.
- **`pub`** on `fn`, `struct`, `enum`, `error`, `interface` and on methods makes them visible to other modules (see Modules below); it also decides the error set rule below.
- **`main`:** the entry point must be `pub fn main()` in the root module, with no parameters, and with no return type or an error union with `void` (`!void`, `E!void`). The generated C `main` stores `argc`/`argv` for `std.os.args`, and returns 0, or 1 after reporting an error that `main` returned.
- **Pointers:** `*T` is read-only, `*mut T` is writable. They are made with `&x` and `&mut x`.
  - `&mut x` needs a writable place: a `var`, or data behind a `*mut`. `&` of a temporary (`&f()`) is an error.
  - Dereference is `p.*`, as in Zig (`*` already starts the type).
  - Field access dereferences one pointer level, as in Go and Zig: `p.x`, and `p.x = 1` when `p: *mut T`. So does indexing a pointer to an array: `a[i]` for `a: *[N]T`.
  - There is no pointer arithmetic. `==` and `!=` compare pointers by address (M6), also a `*T` with a `*mut T`; `<` and the other orderings do not apply.
- **Optionals:** `?T`, with the literal `null`. `null` is a predeclared identifier like `true`, so it is not a keyword.
  - `if x |v| { } else { }` unwraps, as in Zig. `v` is immutable and visible only in the first block.
  - `while x |v| { }` (M6) evaluates `x` before each iteration and runs the body while it has a value; `v` is visible in the body. `continue` evaluates `x` again.
  - `x == null` and `x != null` work, as in Zig (and Go's `nil`).
- **Enums:** `enum Name { A, B { field: T, ... } }`. Variants are separated by `,` or newlines; payload fields are written like struct fields. A variant without payload has no `{}`.
  - A value always names the enum: `Shape.Circle { r: 1.0 }`, `Color.Red`. The shorthand `.Circle { }` is not supported, so there is one way to write it.
- **`match`:** `match x { pattern => body }`. Arms are separated by newlines or `,`. The scrutinee follows the header rule of `if` (no bare struct literal).
  - Patterns: `.V`, `.V { a, b: name, .. }` and `_`. A field binds a variable of the same name, or `field: name`. Without `..`, every field must be listed.
  - Matching a variant twice, and any arm after `_`, is an error.
  - On an integer (M6): integer and character literals (`10`, `-1`, `'a'`), inclusive ranges `'a'..='z'` (`'a'..'z'` is an error that says to write `..=`), and several patterns per arm, `'a', 'e' =>`. Several variant patterns per arm came in M9.5 (see there). Patterns are literals; named constants as patterns wait for a use. A pattern that does not fit the type (E0024), an empty range (E0088), and a value that an earlier pattern already matches (E0057) are errors.
  - Exhaustiveness on integers is exact for every integer type: without `_`, the arms must cover every value (a `u8` with `0..=127` and `128..=255` needs no `_`). The error lists the first three missing ranges.
  - As a statement, an arm body is a block or a call. As an expression, it is an expression (not a block), and all arms must have the same type. With no expected type, the first arm that is not an untyped literal or `null` decides the type.
- **New tokens:** `&`, `|`, `=>` and `.*`. `.*` ends a statement for semicolon insertion, like `)`. M6 adds `^ ~ << >> &= |= ^= <<= >>=` and `..=`; M7 adds `...`.
- **Function types (M7):** `fn(A, B) R`, written like a declaration without names. The result type is there when the token after `)` can start a type (an identifier, `[`, `*`, `?`, `dyn`, `fn`), so `cb: fn(i32)` followed by a newline, `,` or `=` has none. A call of a value that is not a name is a postfix `(args)`: `pick()(x)`, `ops[i](x)`.
- **Bitwise operators (M6):** `& | ^` bind tighter than comparisons and `catch` and looser than `+ -`; `<< >>` bind tighter than `& | ^` and looser than `+ -`. So `x & 1 == 0` is `(x & 1) == 0`, unlike C, and `1 + 2 << 3` is `(1 + 2) << 3`, as in Go's `<<` but not in C. `&`, `|` and `^` cannot be mixed without parentheses (E0087, reported at the second operator), as in Zig, so `a & b | c` is never misread; a chain of one of them (`a | b | c`) is fine.
  - In an `if` or `while` header a `|` at the top level (outside parentheses, brackets and braces) starts the capture, and a `|` right after `catch` always does. So a bitwise or there is written in parentheses: `if (a | b) != 0`. When the capture does not parse, the error says so.
  - Prefix `~` is bitwise not, with the precedence of the other prefix operators.
- **Error sets:** `error Name { A, B }` at top level, with names separated by `,` or newlines. A merged set is a declaration too, `error All = A || B`, as in Zig's `const All = A || B`; `||` is not a type operator, so every set has a name that `rg "error All"` finds.
- **Error values** are written `Set.Name`, like enum values (`return ParseError.Empty`). In `match e`, an arm is `.Name`, like an enum pattern.
- **Error unions:** `E!T`, and `!T` with an inferred set. They are allowed only as a function's return type, not for parameters, fields or variables. `void` is a type name only as their payload (`!void`).
- **`try x`** is a prefix operator with the precedence of unary operators, as in Zig. It works only on error unions; `?T` is unwrapped with `if x |v|`.
- **`catch`:** `x catch |e| { block }` or `x catch |e| expr`; the capture `|e|` is optional. `catch` binds looser than `+` and tighter than comparisons, as in Zig: `f() catch 0 + 1 == 2` is `(f() catch (0 + 1)) == 2`.
  - With a block, the block runs on an error. If the payload `T` is not `void`, the block must end with `return`, `break` or `continue` on every path, or (M9.9) with an expression that is the replacement value.
  - With an expression, the expression replaces the error: it must have type `T` (`f() catch 0`, `f() catch |e| match e { ... }`). If `T` is `void`, it must be a call.
- **`errdefer`** takes a block or a simple statement, like `defer`. It is an error in a function that does not return an error union, because it would never run.
- **Methods** are functions declared in a struct body (`fn` or `pub fn`), in any order with the fields. In the struct, `Self` names it.
  - Enums have methods too (M6), declared in the enum body with the variants, and called the same way (`c.next()`, `Color.name(c)`). In an enum, `Self` names it, also in values: `Self.Red`, `Self.Num { value: v }`. A method cannot have the name of a variant. Enums cannot be converted to `dyn` or satisfy a `where` constraint yet: those are checked for structs.
  - The first parameter decides how a method takes its receiver, as in Zig: `self: Self` (a copy), `self: *Self` or `self: *mut Self`. The name `self` is a convention, not a rule. A function without such a parameter is called only as `Type.f(args)`.
  - `x.m(args)` passes the receiver as the first argument. For `*Self` and `*mut Self`, a pointer `x` is passed as it is, and a place `x` is passed as `&x` or `&mut x`; `&mut` needs a writable place, as for `&mut x` itself. A temporary is never borrowed implicitly (`make().get()` with `self: *Self` is an error). For `self: Self`, a pointer receiver is dereferenced (copied).
  - `Type.f(args)` calls any function of the struct with all arguments written out, also a method: `Counter.get(&c)`.
  - Method names are scoped to their struct: a method can share its name with a top-level function, but not with a field of its struct. Its parameters follow the shadowing rule.
- **Interfaces:** `interface Name { fn m(self: *Self, ...) T }`, one method signature per line, without bodies. The first parameter must be `self: *Self` or `self: *mut Self`, and an error union return type must name its set (`E!T`).
- **`dyn I`** is a type. A `dyn` value is made only by an implicit conversion: a `*T` or `*mut T` where `dyn I` is expected (`show(&mut sq)`, `let s: dyn Shape = &c`).
- **Generics:** a parameter `comptime T: type` takes a type, and a function with one is generic. A function whose return type is `type` is a type function; its body is exactly `return struct { ... }`, an anonymous struct with fields and methods (`Self` is the struct). `struct { ... }` is allowed nowhere else, so every named type still has a declaration that `rg` finds (`struct Name` or `fn Name(...) type`).
  - Only top-level functions have `comptime` parameters: not methods, interface methods or `extern fn`. A type function has only `comptime` parameters.
  - `where` follows the return type, as in Rust: `fn f(comptime T: type, x: T) i64 where T: Show {`. Each constraint is `Param: Interface`; two interfaces are written `T: A, T: B` (there is no `+`).
  - A call passes the type like any argument: `max(i64, a, b)`. `Pool(Node)` is a type wherever a type is written, and also before `.f(...)` and `{` in an expression: `Pool(Node).init(alloc, 16)`, `Handle(T) { index: i, generation: g }`. A type argument that does not read as an expression is written as a type: `f(*Node, p)`, `f([]u8, s)`.
  - A type alias names an instance: `let NodePool = Pool(Node)` (M6, see Type aliases above).
- **The empty slice** is `[]T{}` (or `[]mut T{}`): a null pointer and length 0. A slice literal cannot have elements, because they would need storage that lives somewhere: put them in an array and slice it, or use `alloc.alloc`.
- **Test blocks:** `test "name" { ... }` at the top level. The body is checked like a `!void` function, so it can use `try`. Test names in a module must differ.
  - `ore build`, `ore run` and `ore emit-c` leave test blocks out (they are still type-checked) and need `pub fn main()`. `ore test` does not need `main`. `ore check` needs `main` unless the root module has a test block.

## Types and checking

- **Untyped literals:** an integer or char literal takes the type that the context expects. An integer literal can also become a float type. With no context, an integer literal is `i64` and a float literal is `f64`. In a binary operation, a literal operand takes the type of the other operand. A literal that does not fit its type is a compile error.
- **A `for` range of two untyped literals is `usize`** (`0..4`), as in Zig; if one bound has a type, the literal bound takes it. Loop counters are mostly indices, and the M5 gate test's only compile error was `for k in 0..4` used with a `usize`. `-1..3` is then an error; a signed counter is written `(0 as i64)..4`. Elsewhere an untyped literal with no context stays `i64`.
- **Char literals** (`'a'`) are untyped integer constants whose value is the Unicode code point.
- **String literals** have type `[]u8`. They are UTF-8, and the bytes are followed by a NUL that `len` does not count, so `"text".ptr` can be passed to C as `[*]u8`.
- **Index and slice bounds** must have an unsigned integer type (`u8` to `u64`, `usize`). Untyped literals become `usize`. Signed indices need `as`, so a negative index is never possible. The design doc's examples index with a `u32`.
- **Slice elements are read-only unless the slice type says `mut`.** `[]T` elements cannot be assigned or borrowed with `&mut`; `[]mut T` elements can, wherever the slice is stored (a `let` slice, a field behind a `*T`): the slice type decides, as a pointer type does. So `*Self` stays shallow: it forbids `self.slots = ...` but not `self.slots[i] = ...` when `slots` is a `[]mut T`. Array elements and struct fields can be assigned when the root binding is `var`.
  - A `[]mut T` is accepted where a `[]T` is expected, like `*mut T` for `*T`.
  - Slicing an array gives a `[]mut T` when the array could be borrowed with `&mut` (a `var`, or data behind a `*mut`), as in Zig; otherwise a `[]T`. Slicing a slice keeps its type. String literals are `[]u8`.
- **Slicing an array** requires the array to be stored in a variable or other place, not a temporary value.
- **`.len`** works on arrays and slices and has type `usize`. **`.ptr`** works on slices and has type `[*]T`.
- **`as` casts** are numeric only; pointer types are converted with `@ptrCast` (M7, see C interop).
  - int to int is checked: the program panics in debug and safe mode when the value does not fit the target type. It never truncates silently.
  - float to int is also checked: the program panics on NaN and on values out of range. The conversion truncates toward zero.
  - int to float and float to float use plain C conversion.
- **Integer arithmetic:**
  - `+ - * / %` and unary `-` panic on overflow. `/` and `%` also panic on division by zero. `MIN / -1` and `MIN % -1` count as overflow.
  - `+% -% *%` wrap.
  - `%` is integer-only.
  - `& | ^ ~ << >>` are integer-only. Both operands of a shift have one type, like other binary operators (`x << 3` gives `3` the type of `x`; `x << n` needs `n as T` when `n` has another type), as the milestone fixed; Go and Zig give the amount its own type instead.
  - A shift amount of the bit width or more, or a negative one, panics in debug and safe mode with `shift amount out of range`; in fast mode the amount is masked to the width (as x86 does), so there is no undefined behavior. `<<` drops the bits shifted out and never panics on them, as in Go (Zig panics): hashing shifts bits out on purpose. `>>` of a signed value is arithmetic (copies the sign bit).
- **Equality:** `==` and `!=` work on integers, floats and bools, and between an optional and `null`. M6 adds pointers (`*T`, `*mut T`, `[*]T`, by address) and enums whose variants all have no fields (by tag); an enum with a payload variant is E0025, with a hint to use `match`. Array, slice and error equality are not supported; structs and optionals compare since M9.5.
- **Unused call results:** an expression statement must be a call (or `try`, `catch` or `match`), and a non-void result may be dropped silently. Other expression statements are errors.
- **Error unions must be handled:** a call that returns `E!T` must be the operand of `try` or `catch`, or be returned as is (`return f()`) from a function whose error set has all its errors. It cannot be stored, passed, used in an expression, or dropped as a statement.
- **Implicit wrapping:** a `T` value is accepted where `?T` is expected (a typed `let`, an assignment, an argument, a `return`, a field). This wraps the value; it is not a conversion between types, so it does not break the "no implicit conversion" rule. `*mut T` is also accepted where `*T` is expected, as in Rust and Zig. There are no other implicit coercions.
  - M9.6: the adjustments chain once: one of them (dropping `mut`, an error set into a larger one, a pointer into `dyn I`) and then the wrapping into `?`, so `[]mut T` is accepted where `?[]T` is expected. Dropping `mut` also applies inside `?` and to a returned error union's payload (`return builder.toOwned()` of `E![]mut u8` from an `E![]u8` function, which the browser hit everywhere). These keep the value's representation (`*T` and `*mut T` now share one C type name, as `[]T` and `[]mut T` did); an `E!T` to `E!?T` would need a new value and stays an error.
- **`match` is exhaustive:** without `_`, every variant must have an arm. The error names the missing variants (`missing variant `Shape.Rect``). `match` works on enums, on error values and on integers; on errors, every error of the set needs an arm (`missing error `ParseError.Overflow``), and on integers every value (`missing `0..=47``).
- **An error is identified by its name**, as in Zig: the same name in two sets is the same error. Every error name gets a program-wide value (a `u16`; 0 means no error) in order of first declaration. A merged set `A || B` has the errors of both, and an error value converts to any set that has all of its errors (`ParseError` to `LoadError`). A literal `Set.Name` counts as only that error.
- **Error set checking:** in an `E!T` function, every error that a `return` or a `try` can pass on must be in `E`. The inferred set of a `!T` function is the union of those errors; `return ParseError.Empty` adds only `Empty`. A `!T` function is checked before its callers, which need its set, so a `!T` function that calls itself, directly or through other `!T` functions, is an error.
- **`pub` functions spell out their error set** (`E!T`). `!T` is only for functions that are not `pub`, and for `pub fn main() !void`.
- **Diagnostic codes:** every diagnostic has a code (`E0001`, ...) from the table in `src/codes.rs`: a title, an explanation, a program with the error and the fixed program. A unit test checks that each wrong program reports its code and each fix compiles. Codes are never renumbered or reused; a new kind of error gets the next number. `ore explain <code>` prints an entry.
- **Pattern bindings and `|v|` captures** are immutable copies, and they follow the shadowing rule below.
- **Shadowing** is not allowed in any scope. A `let`/`var` binding, a parameter or a `for` variable is an error when its name is already visible: a local in the same or an enclosing block, a parameter of the function, or a top-level name (`fn`, `extern fn`, `struct`, a global, ...). Sibling blocks and different functions can reuse a name.
- **`isize` and `usize`** are 64-bit. Stage0 assumes an LP64 target.
- **Interface conformance is structural**, as in Go: a struct implements `I` when it has every method of `I`, with the same parameter types after `self` and the same return type. There is no `impl` declaration. It is checked where a pointer converts to `dyn I`, and the error names the missing or different method.
  - A method that takes `self: *mut Self` needs an interface method declared with `self: *mut Self`, and a `*mut T` (`&mut x`). Methods that take `self: *Self` or `self: Self` work from `&x` too.
  - Calls through a `dyn` need no mutability: whether it was made from `&mut` was checked at the conversion.
- **Allocators:** `Allocator` and the error set `AllocError { OutOfMemory }` are items of `std.mem`, and `General` and `Arena` of `std.heap` (they were predeclared before M5). They are built into the compiler, not declared in std's Ore source, for the reasons below; they are used like any std item, after `import std.mem.Allocator` or as `std.heap.General` after `import std`. Messages name them by path (`std.mem.Allocator`). Using one of these four names without an import (and without declaring it) is E0084, with a fix-it that adds the import; a module may declare its own `Allocator`.
  - `Allocator` is a fat pointer like `dyn`: a data pointer and a vtable of byte-level `alloc` and `free` functions. It is not `dyn` of a user-visible interface, because its typed methods take a type or any value, which an interface method cannot express without generics. `General` and `Arena` make one (`gpa.allocator()`), and since M9.7 so does a `*mut S` of a struct with byte-level `alloc` and `free` methods (see M9.7). `resize` waits for a container that grows.
  - `General.init()`, `Arena.init(backing)`; `x.allocator()` and `x.deinit()` take `self: *mut Self`, so the variable must be a `var`.
  - `alloc.create(value)` returns `AllocError!*mut T`, with the memory set to `value`. Ore has no uninitialized variables (`let` and `var` need an initializer), so heap memory starts initialized too. `alloc.create(Node)`, with a type, is an error that says to pass the initial value.
  - `alloc.destroy(p)` takes a `*T` or `*mut T`.
  - `alloc.alloc(value, n)` returns `AllocError![]mut T` with `n` elements, each set to a copy of `value`, for the same reason as `create(value)`: memory starts initialized. `n` is an unsigned integer. `alloc.alloc(T, n)`, with a type, is an error that says to pass the value. `n == 0` gives the empty slice without allocating.
  - `alloc.free(s)` takes a `[]T` or `[]mut T` from `alloc.alloc`; freeing an empty slice does nothing. Freeing a slice that does not start an allocation (`s[1..]`) is freeing memory the allocator did not allocate.
  - `alloc.alloc` and `alloc.free` stay allocator intrinsics: an interface method cannot take a type or any value, and `Allocator` is not an interface (see above). `resize` waits for a container that grows in place.
- **Test builtins:** `@expect(cond)` and `@expectEqual(expected, actual)`, in Zig's argument order. `@expectEqual` compares integers, floats, `bool` and `[]u8` (by bytes); a literal takes the type of the other side. They can be used in any function.
  - `@testAllocator()` is the leak-checked allocator of the running test. It can be used only in a `test` block; other functions take an `Allocator` parameter.
- **`extern fn` signatures** use C-compatible types (M7, see C interop). Calls go straight to the C symbol of the same name (the name without its module).
- **Slicing a `[*]T`** needs both bounds, `p[lo..hi]`, and gives a `[]mut T` (M7; it was a `[]T` before), as the milestone says: C memory is as writable as the pointer, which does not track read-only data. Only `lo <= hi` is checked: there is no length. It turns a C string or buffer into a slice (std uses it for `std.os.args`), as in Zig.
- **Generics are checked where they are defined** (the open question in the design doc, answered as it leans): each generic's body is checked once, with each `comptime` type as an abstract type parameter. A value of a type parameter `T` can be moved, copied, pointed to (`*T`, `*mut T`), wrapped (`?T`), stored in arrays and slices, and allocated (`alloc.create`, `alloc.alloc`). It has no fields, no operators (`==` too) and no methods, except the methods of the interfaces of its `where` constraints, called as on a struct (`x.area()`, with the interface's receiver: `self: *mut Self` needs a writable place). So an error in a generic is reported in the generic even if it is never instantiated.
  - An instantiation checks every constraint: the type argument must be a struct that implements the interface (structurally, as for `dyn`, through a `*mut T`). The error is at the instantiation (`Pool(Point)`, `twice(i32, 3)`), names the constraint and its position, and says why the type does not satisfy it. A type parameter of another generic satisfies a constraint only if it has the same one (`add where U: Show`).
  - Instances are memoized by their type arguments: `Pool(Node)` written twice is one type, and `Handle(Node)` and `Handle(Edge)` are different types even when `T` is not used in the struct. In messages an instance is named `Pool(Node)`.
  - Code is monomorphized: each instance is checked again with its concrete types (its errors are those of the generic, which were reported there), and gets its own C code. A generic is never emitted for its abstract parameters. Every method of a type function's struct is generated for each instance, used or not.
  - A generic function, and a method of a type function's struct, spells out its error set (`E!T`): an inferred set would depend on the body of each instance.
  - `comptime` parameters follow the shadowing rule like other names.
  - A generic that instantiates itself with a larger type (`Nest(?T)` in `Nest(T)`) would never end: an instance whose type arguments nest instances and other types more than 32 levels deep is an error (E0080). M9.8: this replaced a limit of 64 instances per generic, which the browser hit with `List(T)` (a program has as many instances as it needs; `tests/cases/many_instances.ore` has 200 of `List`).
  - Out of scope (M4): `comptime` values other than types, `comptime` blocks and compile-time execution beyond type functions, and compile-time I/O.
- **Fix-its:** a fix-it is offered only where the edit is certain to fix the error: `let` to `var` for an assignment or `&mut` of a `let` binding; joining `}` and `else` when only a line break is between them and the statement before is an `if` without `else`; the missing trailing `,` of a multi-line call or literal when the closer follows on the next line; renaming an unknown type, variable, function or field to the only visible name one edit away (insert, delete, replace, or swap two adjacent characters), for names of at least 3 characters. Missing `match` arms get no fix-it: the patterns would be certain but no arm body is (there is no placeholder such as `todo`), and an empty arm would hide the missing case. `create(T)` with a type keeps its hint in the message: the initial value is not known.
- **Error recovery:** every stage reports all of its errors, sorted by position and deduplicated, at most 50.
  - The lexer skips the rest of a bad line.
  - The parser skips a bad statement up to the end of its line (using brace depth and indentation), and a bad declaration up to the next line that starts with a declaration keyword.
  - If the lexer or parser reported errors, sema does not run, as in Go. A syntax error never causes type errors.
  - Sema drops a statement with an error and goes on. A variable whose type is unknown (bad initializer, unknown type, rejected declaration) gets an error type, and its uses are not reported again.

## Modules (M5)

- **A module is a directory** (Go's rule): every `.ore` file directly in it belongs to it, and they share one namespace, so a file uses the others' declarations without imports. A name declared twice in a module is E0015, also across files.
- **The root module** is what the command gets: `ore build/run/check/test/fix dir` compiles the directory module `dir`; `ore ... file.ore` compiles that file as a module of its own, and the other files in its directory are not part of it (so a directory of single-file programs, such as `tests/cases`, keeps working). `ore build dir` names the executable after the directory.
- **`import a.b`** finds the module in the directory `a/b` under the root module's directory, from any module (paths are rooted, as in a Go module, not relative to the importing file). `std` and `std.*` are embedded in the compiler (the sources in `std/`, through `include_str!`), so `ore` works from any directory; a directory named `std` is never imported.
  - `import a.b` binds `b` in the importing file, and `import a.b.Name` binds the single item `Name` (which must be `pub`). There is no glob and no renaming. Imports are per file, as in Go.
  - After `import a`, a path reaches `a`'s items and also its submodules: `std.fs.open` after `import std`, as in Zig. A path is resolved one name at a time; when a module has both an item and a subdirectory of one name, the item wins. So every name from another module traces to one import line in the file.
  - A name imported twice, or imported and also declared in the module, is E0015. A local, parameter, capture or pattern binding cannot shadow an import (E0016), nor, in a module other than the root, a top-level name of its module (module resolution checks that; sema checks the root module as before).
  - An unknown module or member is E0081, an item that is not `pub` E0082, an import cycle E0083 (reported at the import or use that closes it: `` import cycle: `a` -> `b` -> `a` ``), a module used as a value or type E0085. A module that has syntax errors is not resolved, and lookups into it are not reported.
- **Visibility:** only `pub` items (functions, structs, enums, error sets, interfaces) and `pub fn` methods can be used from another module. Struct fields and enum variants are visible wherever their type is, as in Zig: `pub` on fields would add a rule to every struct literal. A method that is used only through an interface of another module, by `dyn` or a `where` constraint, needs no `pub`, because conformance is structural; an instance of a generic is not checked again for `pub`.
- **Canonical names:** module resolution rewrites every name of a module other than the root to `a::b::Name` (`std::fs::open`, `util::Thing`; methods stay `Thing.method`), so all modules become one AST for sema, and names of the root module stay as written. Messages show `::` as `.`: `std.fs.File`. Only the root module's `test` blocks are compiled; they are numbered across its files.
- **Order of checking:** the lexer and parser run on each file, module resolution on the program; if any of them reports errors, sema does not run. Diagnostics are sorted by file (root files first, in name order, then the modules in load order) and position.
- **Positions:** a `Span` has a file index. Diagnostics, `#line` directives, panics, leak reports and error return traces name the file of each position (`std/fs/fs.ore:70:9` for std). The runtime gets a position as two `int`s, with the file index in the line's upper bits.

## std (M5)

std is small, written in Ore over `extern fn` into libc, and embedded in the compiler. `ore spec` lists its whole API; `tests/spec.rs` checks that the spec names every pub function.

- **`std.fs`:** `open(path) OpenError!File` (read-only), `stdin()`, `stdout()`, `stderr()`; `File` has `readAll(alloc) ReadError![]mut u8`, `write(bytes) WriteError!void` and `close()`, all taking `self: Self`, so that Example 1's `let file` can call them. `error OpenError { NotFound, AccessDenied, OpenFailed }`, `error ReadError { ReadFailed, OutOfMemory }`, `error WriteError { WriteFailed }`. `File.write` flushes C stdio first, so it stays in order with `@print`. `readAll` gives the empty slice for no input (nothing to free), and otherwise a slice that starts its allocation, for `alloc.free`.
- **`std.mem`:** `Allocator`, `AllocError` (built in), `eql(a, b)` and `copy(dst, src)` on bytes.
- **`std.heap`:** `General` and `Arena` (built in).
- **`std.log`:** `err(format, args...)` and `info(format, args...)` write `error: <message>` and `info: <message>` and a newline to stderr, after flushing stdout. Ore has no variadic functions, so both are compiler builtins, written as calls of std items: the format must be a string literal, or (M9.5) a top-level `let` constant whose value is one; each `{}` in it takes the next argument, which must be an integer, float, `bool`, `[]u8`/`[]mut u8`, or an error value (written as its name); the count must match (E0086). There is no other formatting and no escape for `{}`. When `main` returns the error afterwards, as in Example 1, the error shows twice: once in the log line, once in the `error: Name` report.
- **`std.os`:** `args(alloc) AllocError![][]u8` (the slice is allocated, the arguments are not copied) and `exit(code)`, which is libc's `exit` declared `pub extern fn` (stdio is flushed; defers do not run).
- **Runtime hooks:** std calls three C functions of the runtime through `extern fn`: `ore_std_argc`, `ore_std_argv` (the arguments that the C `main` stored) and `ore_std_open` (a path slice that is not NUL-terminated, to `open`, returning the descriptor or `-errno`, because `errno` is a macro in C).
- `ore run <path> -- args` passes `args` to the program.

## C interop (M7)

- **No C headers, still (M7):** the generated C declares every `extern fn` from its Ore signature and defines every `extern struct` from its Ore fields, so the layout is what the Ore declaration says. It must match the C library's header; nothing checks that. This keeps user declarations from clashing with system headers, and the Ore file is the one place that says what the program assumes about C.
- **C-compatible types:** integers, floats, `bool`, `*T`, `*mut T` and `[*]T` to a C-compatible `T`, `?*T`, `?[*]T` and `?fn(...)` (C pointers that may be null), `extern struct`s, and `fn(A) R` whose types are C-compatible. Arrays only as fields of an `extern struct` (or behind a pointer, `*[4]u8`): Ore arrays are values, and C passes an array argument as a pointer. Integers are the `<stdint.h>` types (`i32` is `int32_t`, C's `int`), `usize` is `size_t` and `isize` is `intptr_t`. Slices, Ore structs, enums, error types, `dyn` and optionals of non-pointers are not C-compatible (E0052): an Ore struct's layout is the compiler's, so a pointer to it reaches C only through `@ptrCast` (a C `void *` is `?[*]u8`).
- **`extern struct Name { ... }`:** fields in declaration order, with C's alignment and padding (emitted as a C struct; an array field is a struct wrapping a C array, which has the array's size and alignment). Ore structs are laid out the same way today, but only `extern struct` promises it and checks its fields. An `extern struct` can have methods. One with no fields is an opaque type for pointers (`extern struct Curl {}`, `?*mut Curl`). A prefix of the C fields is enough when the value is only read through a pointer (SDL owns `SDL_PixelFormat`); copying it or `@sizeOf` then gives the prefix only.
- **Pointers to C:** a `*mut T` parameter takes `&mut x` directly, so out-parameters need no cast; there is no implicit conversion from `*mut T` to `[*]T` (the milestone allowed either; one less rule). `[*]T` is unchecked: `p[i]` reads and writes without a bounds check (`p[i] = v` is allowed whatever the pointer came from), and `p[lo..hi]` gives a `[]mut T`.
- **Optional C pointers:** `?[*]T` and `?fn(...)` are C pointers that may be null, like `?*T` (before M7, `?[*]T` was a `{ has, val }` struct). They compare with `null` and unwrap with `if p |q|`.
- **`@ptrCast(T, p)`:** `p` and `T` are pointer types: `*T`, `*mut T`, `[*]T`, or `?` of one. It cannot make a `*T` (or `?*T`) writable as `*mut T`, nor an optional pointer non-optional (unwrap it first); everything else is allowed, since C pointers are unchecked anyway (E0092). It is the only pointer conversion.
- **`@sizeOf(T)`** is C's `sizeof`, a `usize`, for any type. clang computes it, so it is not a constant for a global's initializer.
- **`@zeroed(T)`:** numbers, `bool`, optional pointers, `extern struct`s whose fields are all of these, and arrays of them (E0093 names the field that cannot be zero, such as a non-optional pointer). A struct is cleared with `memset`, so its padding is zero too. Arrays are allowed because a C buffer is the common case (`var buf = @zeroed([256]u8)`); an Ore struct is not, because its value is made with a literal.
- **Variadic C functions:** `...` ends the parameters of an `extern fn` without a body, after at least one parameter (E0091 otherwise). The C declaration has `...`, so clang applies C's default argument promotions (`f32` to `double`; `i8`, `i16`, `u8`, `u16` and `bool` to `int`). An untyped integer literal after `...` is an `i32` (C's `int`, what `%d` reads), not the `i64` it is elsewhere; an untyped float is an `f64`. Every argument must be C-compatible. A variadic function is not a value.
- **Function values:** a top-level function that is not generic is a value of type `fn(A, B) R`; so is an `extern fn` that is not variadic. Methods are not (call `Type.m(x)` in a function), nor are generic functions (they need type arguments). Function types are equal when their parameter and result types are equal. A function value is a C function pointer: Ore functions are C functions, so one whose types are C-compatible can be passed to C as a callback. `f(x)` calls a local or global of function type, `s.f(x)` the field `f` when `s`'s struct has no method `f` (a method and a field cannot share a name), and `?fn` must be unwrapped first (E0095). There is no `==` on function values yet. A global can hold a function (`let HANDLER: fn() = run`).
- **Function types with errors:** a function type can return `E!T` with a named set, like a function; `!T` is an error there (the inferred set has no name to write).
- **`pub extern fn` with a body** exports the function to C under its own name (without the module, not `static`); its signature must be C-compatible, and it cannot be variadic. Ore calls it by that name too. `extern fn` with a body and without `pub` is E0011: exporting is the point of `extern` on a body, and the design doc spells it `pub extern`.
- **One C function, one signature:** every declaration of a C symbol, in any module, must have the same C signature (pointer kinds do not matter: `*T`, `*mut T`, `[*]T` and `?*T` are all `T *`), and at most one `pub extern fn` defines it (E0096). Before M7 this was a rule that clang enforced with an error that looked like a compiler bug.
- **`@link("name")`** is a top-level declaration, the only builtin there (E0094). The names of every module are collected in order of first appearance. `ore build`, `ore run` and `ore test` pass them to clang after the program: `pkg-config --cflags --libs name` when `pkg-config` knows `name`, `-lname` otherwise, `-framework Name` for `framework:Name`. They follow `-x none`, so a library path from `pkg-config` is not read as C. `ore emit-c` prints only the C. A failed link says to check that the libraries are installed.

## std (M8)

The rest of std is Ore too: no container or text function is a compiler builtin.

- **`Allocator.resize(s, n, fill) AllocError![]mut T`** is the one new allocator intrinsic: memory starts initialized, so growing needs a value for the new elements, and a type parameter has no "zero". It allocates `n` elements, copies `min(s.len, n)` from `s`, fills the rest, and frees `s` on success (realloc semantics; on `OutOfMemory` `s` is unchanged). The vtable is still `alloc` and `free`; there is no in-place growth. It is lowered as `alloc.alloc` with an old slice.
- **Containers fill new memory with a value they were given.** `List.append`/`insert`, `StrMap.put`, `IntMap.put` and `Pool.insert` grow with the inserted value as the fill, so `init` allocates nothing and needs no value.
- **`std.list.List(T)`:** a slice, a count and the allocator; it doubles (8 elements first). `items()` returns `[]mut T`; a method cannot share a field's name, so the fields are `buf` and `count`. Bad indices panic through the bounds checks (there is no `@panic`).
- **`std.map`:** open addressing, linear probing, power-of-two tables at most 3/4 full, backward-shift removal (no tombstones). `StrMap` hashes with FNV-1a and does not copy keys (as Zig's `StringHashMap`). `IntMap(K, V) where K: Integer` (after M8; M8 had `where K: Key` with `interface Key { fn key(self: *Self) u64 }`, because an integer type could not satisfy a constraint) stores each key with its 64 bits, which are compared for equality and mixed with the SplitMix64 finalizer for the hash. The bits are `k as u64`, or for a negative key (`k as f64 < 0.0`, the only sign test without operators on `K`) its two's complement computed through `i64`, since `as` panics on a negative value. A struct key is stored by its integer field. Iterators hold the table slice and return entries with a `*mut V`.
- **`where T: Integer` (after M8)** is a built-in constraint that only integer types satisfy; with it, a `T` value converts with `as` to any numeric type, with the usual checks in the instance (`as` panics when the value does not fit). Nothing else: no operators, comparisons or literals on `T`, and no `as T`. It is the smallest addition that lets a generic take integer keys: `Integer` is a predeclared name (declaring it is E0014), not an interface, because no interface method can describe a conversion, and the rest of an integer's operations would need rules for untyped literals of an unknown integer type. An interface constraint and `Integer` on one parameter cannot both be satisfied (integers have no methods). An instance made in a signature before its constraint check fails no longer reports errors in its methods (the error at the instantiation is enough).
- **`std.sort.sort(comptime T, items: []mut T, less: fn(T, T) bool)`** (after M8): the order is a function value, as in Zig's `std.sort` (without its context argument; a closure can come later). Insertion sort up to 12 elements, heap sort above: O(n log n), no allocation and no error. It is not stable, so a sort that must keep ties in order breaks them in `less`, as the word-frequency test does; a stable sort needs a buffer (an allocator) or O(n log² n) merges, and waits for a use.
- **`std.text`:** ASCII-only case and whitespace. `split` keeps empty pieces (Zig's `split`). `decode`/`encode` follow Go: invalid input gives U+FFFD instead of an error. `toLower` works in place (copy first if needed). `parseInt` accumulates negatively to reach the i64 minimum.
- **Floats in text:** `Builder.appendFloat` gives the text of `@print` (`%g`: 6 significant digits). `snprintf` is variadic, so std calls libc's non-variadic `ecvt` for the correctly rounded digits and lays them out in Ore (NaN, infinities, zero and the sign are handled before, so platform differences of `ecvt` do not show). `parseFloat` checks the syntax in Ore, copies the text into a 64-byte NUL-terminated buffer and calls `strtod` (so at most 63 bytes). musl has no `ecvt`.
- **`std.math`** is `f64` only (no generic arithmetic); `sqrt`, `floor`, `ceil`, `round` and `pow` are libm functions declared `pub extern fn`, and clang now links `-lm`.
- **`std.pool`** is Example 3's `Pool(T)`/`Handle(T)`, as in `tests/cases/pool.ore`.
- **`std.time`:** `monotonicMs()` and `sleep(ms)`; `sleep` passes a `[2]i64` as the C `timespec` to `nanosleep` and retries when interrupted.
- **`std.fs`:** `create` (write-only, created with mode 0644 or truncated), `exists` (`access`), `readFile(alloc, path) ReadFileError![]mut u8` with `error ReadFileError = OpenError || ReadError`.
- **`std.mem`:** `copy` (now `memmove`, so overlap is fine), `set`, `indexOf` of a byte, all on bytes.
- **`std.testing.allocator()`** is the same intrinsic as `@testAllocator()`, with the same rule (test blocks only); both stay.
- **Runtime hooks** added: `ore_std_create`, `ore_std_exists` and `ore_std_monotonic_ns`, because `O_CREAT`/`O_TRUNC` and `CLOCK_MONOTONIC` have different values on macOS and Linux and Ore has no conditional compilation.
- `tests/spec.rs` also requires the pub methods of std's type functions (`List.append`) in the spec.

## Toolchain (M5)

- **`ore spec`** prints `docs/spec.md`, embedded in the binary: one Markdown language reference, meant to be all that an AI agent needs to write Ore. It must stay within about 30k tokens (counted as characters / 4); the limit was 20k until M6 raised it for the language that the browser needs. In it, a ` ```ore ` block is a complete program that `ore check` accepts, and a ` ```ore-error ` block one that it rejects; `tests/spec.rs` checks both, and that every pub function and method of std is named as `name(`. Other fenced blocks are not checked.
- **`ore check --json`:** each diagnostic has a `"file"`, the file of its position and of its fix-it's edits. `ore fix` applies the fixes of each file to that file and never writes std.
- `ore test --json` failures have no file yet (a test's failure in another file of the module shows only its line and column there; the text output names the file).
- Code examples of `ore explain` can be several files: lines `// file: path` start each one, and the code table's test writes them to a directory and checks `main.ore`.

## Formatter and docs (M9)

- **`ore fmt` is a token-stream pretty-printer, not an AST printer.** The parser drops comments and some spelling (`0xff`, escapes), so printing the AST would lose them. The formatter lexes the file, recovers each line's comment from the text after its last token, and rebuilds every line from the tokens' source text.
- **Line breaks are never moved.** Newlines end statements, so joining or splitting lines could change the program. Keeping them means the token stream, terminators included, is unchanged; `fmt::format` checks this before it returns. Diagnostics keep their lines, except that a dropped blank line moves later lines up (`format_mapped` returns the line map; `tests/fmt.rs` compares diagnostics through it). Long lines are not wrapped.
- **Indentation:** each bracket that stays open at the end of a line indents the following lines by one level from the line that opened it; a line starting with a closer gets that line's indentation. A line that ends without a terminator and not with an opener or `,` (a binary operator, `=`, `=>`) makes the next line a continuation, one level deeper. A `{` opened on a continuation line indents from the statement, as gofmt does: `if a &&\n    b {` has its body one level in.
- **Spacing** comes from each token's role, decided from the token before it: `-`, `*`, `&` are binary after an operand and prefix otherwise; `!` after a name is the `E!T` of an error union; `(` and `[` after an operand are a call and an index, else a group and a type prefix (`[]u8`, `[*]T`); the `)` of `fn name(...)` or `fn(...)` is followed by a return type (`) *T`, `) !void`); a `{` after an array or slice type is an array literal (`[3]u8{1, 2}`, no inner spaces) unless it is a function body; `|v|` is a capture after `catch` or before `{`; `in` is a keyword in a `for` header. Everything else gets a space on both sides, except after `(`/`[`, before `)`/`]`/`,`/`:`, and around `.`, `..`, `..=`, `.*`, `.?`.
- **Comments:** kept verbatim (trailing blanks removed); a comment-only line is indented like a statement there. Two or more consecutive lines with trailing comments align them one space after the longest line, as gofmt does; a lone trailing comment gets one space.
- **Refused input:** a file that does not lex, or whose brackets do not match (the indentation would be meaningless), is reported and left unchanged. Other syntax and type errors do not matter.
- **The repo is formatted:** `ore fmt` changed only three trailing comments in `tests/`; every other `.ore` file in `tests/` and `std/`, and every example in the spec, was already canonical. Three error tests are refused (a bad escape, unmatched brackets).
- **`ore doc --signatures` is token-based too**, so it documents modules with type errors. A doc comment is the run of `///` lines right above a declaration or member (no blank line between). Struct fields and enum variants are always listed (they are visible wherever the type is); methods only when `pub` (all of an interface's). A type function shows its returned struct. A module's leading comment block, when a blank line ends it, is printed as the module's documentation (std's headers describe the compiler-provided items this way). Submodules of a directory are named by import path; `std` and `std.<name>` always mean the embedded std, even if a directory `std` exists.

## Semantics and codegen

- **Evaluation order is left to right:** call arguments, binary operands, struct literal fields (in source order) and array elements. OIR fixes this order by computing every operand into a temporary.
- **Defer timing:**
  - `return` evaluates its value first and then runs the pending defers, innermost first.
  - `break` and `continue` run the defers of every scope up to and including the loop body.
- **Output builtins:** `@print(x)`, `@println(x)` and `@println()` print an integer, float (`%g`), bool or `[]u8`. They write through libc stdio, so their output stays in order with `extern fn puts`/`putchar`.
- **Panics:**
  - A panic flushes stdout and then writes `file:line:col: panic: <reason>` to stderr.
  - It ends with `abort()`, which gives exit status 134 from `ore run`.
  - For an arithmetic panic, the position is the operator. For an index or slice panic, it is the `[`.
- **No libc headers:** the generated C includes only `stdint.h`, `stddef.h` and `stdbool.h`, so user `extern fn` declarations cannot conflict with libc headers (M7 keeps this, see C interop). The runtime calls libc through asm-labelled aliases such as `ore_rt_printf`; `errno` is read through `__error` (macOS) or `__errno_location` (Linux).
- **Value types:** arrays are emitted as C structs (`struct { T a[N]; }`), so they are copied by value like structs.
- **Optional layout:** `?*T`, `?[*]T` and `?fn(...)` are C pointers that may be null, the same size as the pointer. Every other `?T` is `struct { bool has; T val; }`.
- **Enum layout:** a `uint32_t` tag (the variant's index in the declaration) and a union with one struct per payload variant. `match` is lowered to an `if` chain on the tag; the last arm needs no test. A `match` on an integer is an `if` chain too, each arm testing its values and ranges.
- **Error union layout:** `struct { uint16_t err; T val; }`, where `err` is 0 for no error; `!void` has only `err`. Unions with the same payload share one C type. An error set value is a `uint16_t`.
- **`errdefer` timing:** an `errdefer` runs, in LIFO order with the `defer`s, when its scope is left by a `return` of an error, by a `return f()` whose union holds an error, or by a `try` that passes an error on. It does not run at the normal end of a block, on `break` or `continue`, or on a `return` without an error.
- **Error return trace (debug mode only):** every `return` of an error and every `try` that passes one on adds its position. When `catch` handles an error, that is, its body ends normally or leaves with `break`, `continue` or a `return` without an error, the entries added since the `catch` started are dropped. Up to 64 entries are kept.
- **An error returned from `main`** flushes stdout, writes `error: <Name>` to stderr, and in debug mode then `error return trace:` and one `file:line:col` line per entry, where the error started first. The exit status is 1. Safe and fast mode record no trace, so they print only the first line.
- **Recursive types:** a struct or enum that contains itself by value (also through an array or `?T`) is an error. Through a pointer it is fine.
- **`#line` directives** come before every generated statement so that debug info points to the `.ore` source.
- **C names:** a function type is a `typedef` of a C function pointer, `ore_F<n>_` followed by each parameter and the result type, each with the length of its name first. A `pub extern fn` keeps its own name. Otherwise a function is `ore_f_name`, a method `ore_m_<len><Struct>_<method>` (the length keeps the names apart), and test `N` is `ore_t_N`. The name of an instance (`Pool(Node)`, `max(i64)`) is written in C as `0` (which starts no Ore name) followed by the name with `_` doubled and other characters as `_` and two hex digits: `ore_s_0Pool_28Node_29`.
- **`alloc.alloc`** asks the allocator for `n * sizeof(T)` bytes (`OutOfMemory` when that overflows), then stores `value` into every element. Leak and double-free tracking treat the allocation like one from `create`, at the position of the `alloc` call.
- **`dyn I` layout:** `struct { void *ptr; const struct ore_VT_I *vt; }`. The vtable has one function pointer per interface method, in declaration order. Each (interface, struct) pair that is converted gets one static vtable of thunks; a thunk casts `ptr` back to the struct pointer (or copies the value for `self: Self`) and calls the method.
- **`General`** calls libc `malloc` and `free`.
  - In debug mode each block has a 64-byte header before it: the allocator, the size, a state (live or freed) and the positions of the `create` and `destroy` calls. Live blocks are in a doubly linked list, oldest first, so allocation and free take constant time and the leak report keeps allocation order (M9.7; before, every allocation got a record that `free` found by scanning the list from the oldest, and freed memory was kept until `deinit`, so a program that allocated and freed a million times was quadratic: `fib(22)` in the browser's JavaScript interpreter took 40 s).
  - A freed block is filled with `0xDD` and goes into a FIFO quarantine of at most 32 MiB (headers included) before libc gets it back, as AddressSanitizer does. While it is there, its address is not reused: a second free panics at the second `destroy` with `double free of memory allocated at F:L:C and already freed at F:L:C`. When it leaves the quarantine, or at `deinit`, its bytes are checked: one that is not `0xDD` panics with `use after free: memory allocated at F:L:C and freed here was written after it was freed`, at the `destroy`. Reads after free are not detected (they read `0xDD`), and a double free of a block that already left the quarantine is not caught: that is the price of reusing memory. Freeing memory that this allocator did not allocate (a pointer that is not 16-aligned, or whose header does not name this allocator) also panics.
  - `deinit` writes `file:line:col: leak: N bytes allocated here were never freed` to stderr for each allocation that was not freed, in allocation order, then frees all memory. A leak does not change the exit status of a program; under `ore test` it fails the test.
  - In safe and fast mode there are no headers: `destroy` is `free`, `deinit` does nothing, and a double free or use after free is undefined behavior.
- **`Arena`** takes chunks of 4096 bytes (more for a larger value) from its backing allocator and bumps a pointer in the newest chunk. `destroy` does nothing; `deinit` gives every chunk back. A leaked arena shows up in its backing allocator as chunks allocated at the `create` that needed them.
- Alignment is at most 16 bytes, which `malloc` gives. When an allocator returns no memory, `create` returns `AllocError.OutOfMemory`.
- **`ore test`** compiles all tests of the program (M9.5: of every module but std's) into one executable whose argument is the index of the test to run, and runs each selected test in its own process. So a panic, a failed assertion or a crash ends only that test.
  - A failed assertion writes `file:line:col: assertion failed: <reason>` to stderr and exits with status 1. The reason is `condition is false` or `expected X, found Y`.
  - After the test body returns, a returned error is reported as `main` reports it (with the error return trace in debug mode), and then the leaks of `@testAllocator()`. The test allocator records allocations in every mode.
  - A test passes when its process exits with status 0. The output format and the `--json` schema are in the README.

## Differences from the design doc (to resolve later)

- The doc's examples use `pub fn main() !void`. Stage0 also accepts `pub fn main()` with no return type.
- The doc shows structs only as anonymous type expressions (`struct { ... }`, returned from type functions) with newline-separated fields. Stage0 uses a named declaration, `struct Name { ... }`. If type functions arrive, this might become `let Name = struct { ... }`.
- The doc shows `defer` only with a call (`defer f.close()`). Stage0 also accepts an assignment or a block.
- The doc has no `@` builtins. `@print` and `@println` write to stdout; `std.text.Builder` formats into memory; `std.log` writes to stderr.
- Example 1 (`readConfig` and `main`) compiles and runs verbatim (`tests/example1/app/main.ore`); `Config` is supplied in `config.ore` of the same directory module. `std.heap.General`, `std.mem.Allocator` and `std.log.err` are compiler builtins exposed as std items (see std above), not Ore declarations.
- The doc's `ore doc --signatures <module>` exists since M9; `ore spec` also names every std function.
- The doc's `Allocator` interface has `alloc`, `resize` and `free`. Stage0's vtable has `alloc` and `free`, and Ore code uses the typed `create`, `destroy`, `alloc`, `free` and `resize` (which may move, and takes a fill value).
- Example 3 declares `slots: []Slot(T)` and then takes `&mut self.slots[h.index]`. With slice elements read-only by default this does not compile, so `tests/cases/pool.ore` declares `slots: []mut Slot(T)`; the rest of `get` is the doc's text. The doc's `Pool(T)` is in `std`: since M8 it is `std.pool` (`tests/cases/std_pool.ore`); `pool.ore` still declares `Pool`, `Slot` and `Handle` itself. Its `Pool` keeps the allocator that `init` takes, allocates on the first `insert` (there is no value to fill the slots with before), and moves to a larger allocation when full.
- The doc does not say where `where` goes; stage0 puts it after the return type, as Rust does.
- The doc says `General` detects use-after-free in debug mode. Stage0 (M9.7) detects writes after free when the block leaves its quarantine; reads are not detected.
- The doc says tests use a debug allocator by default. Stage0 spells it `std.testing.allocator()` or `@testAllocator()`; tests ask for it explicitly. Examples in doc comments do not run as tests yet.
- The doc's `FixedBuffer` allocator does not exist yet.

## Ergonomics from the browser (M9.5)

The browser written in Ore (`browser/COMPILER_GAPS.md` on its branch) listed what hurt. Each change below answers one entry.

- **Several variants per `match` arm:** `.A, .B => ...` on enums and on errors, like the integer patterns. Such an arm binds no fields, since the variants' fields differ in names and types; a variant with fields is listed as `.V { .. }`, as in a single-variant arm, so dropping a payload stays visible. A binding there is E0097, which says to give the variant its own arm. Shared-name bindings were left out: they would need equal field types and a rule for what the binding means. A variant listed twice in one arm is E0057, like a variant matched by an earlier arm. Lowering tests the tag against the arm's tags (one `||` chain).
- **`[_]T{...}`:** the parser counts the elements and builds `[N]T{...}`, so nothing after it knows the difference. `[_]T` anywhere else (a parameter, `@sizeOf`) is E0045, which says that a type needs the length. A generated table no longer needs its length counted by hand.
- **`==` on optionals and structs:** `?T == T` wraps the `T`, and two `?T` are equal when both are `null` or both hold equal values, so `f() == E.A` reads as the browser wanted (false when `f()` is `null`). A struct compares field by field when every field compares (numbers, `bool`, pointers by address, enums without fields, optionals and structs of those), which covers `Handle(T)`; a struct with a slice, array or payload enum field is E0025, which names the field. Floats compare as C does (`NaN != NaN`). Comparison stops at the first field that differs; it has no side effects to skip. The "use `as` to convert" hint of a mismatch is given only when both sides are numbers, since `as` converts nothing else.
- **`orelse`, `.?` and `unreachable` (Zig's spelling):**
  - `x orelse d` gives the value of the optional `x`, or `d`, which is evaluated only for `null`. It binds like `catch` (level 4). The fallback can also be a block, which must leave (`return`, `break`, `continue`) or end in `unreachable` (E0067, as for `catch`), or a bare `return [value]`, `break` or `continue`, which is that block in one line: `let i = find(x) orelse return`. `catch` accepts the same bare jumps, so the two read alike. `orelse` on an error union is E0098, which points to `catch`.
  - `x.?` unwraps and panics on `null` (`unwrap of null`, at the `.?`). It is a place when `x` is one, so `pool.get(h).?.depth = 7` and `opt.?.n += 1` write in place. It is one token, so a line that ends with it ends the statement.
  - `unreachable` is a keyword expression (not `@unreachable()`), as in Zig: it reads well after `orelse` and `=>`. It panics with `reached unreachable code`; its type is whatever the context expects (the arm types of a `match`, the payload after `orelse`), and as a statement it ends a path like `return`, so a function may end with it. `let x = unreachable` has no type to take and is E0030.
  - In `fast` mode the checks are left out and reaching them is undefined behavior (`__builtin_unreachable()`), like the other runtime checks. This makes two keywords (30 in all); a builtin would have needed parentheses in the common `orelse unreachable`.
- **`return f()` of a `void` call:** allowed in a function that returns nothing or `E!void`; it is the call and then `return` (so `defer`s run after the call). Before, a helper changing from `!void` to `void` broke every `return helper()`. A `void` call in a function that returns a value is still E0030 or E0049.
- **`ore test` covers every module:** the tests of each module of the program (the root module and every module it imports, directly or not; not std) are checked with the program and run by `ore test`, numbered across the program. A test is a function of its module, so it can call the module's private functions and import its siblings as the module's code does. A non-root test shows as `test "html: name"`, and `--filter` matches that text; `--module html` runs only module `html`'s tests (`--module` naming a module without tests is an error that lists the modules with tests). The browser could not test `html/` because `ore test browser/html` resolves imports from `browser/html`; finding a project root from a marker file was the other option, but the program's directory already is that root. When an import is not found and a directory above the root module has it, E0081 says to give that directory and `--module`.
- **Smaller fixes:**
  - `std.log.err(USAGE)` with `let USAGE = "..."` works: the format is read from the constant's value at compile time, as from a literal. A `var` global or a local is still E0086, since the `{}` count is checked when compiling.
  - A local named like an import is still E0016 (no shadowing, imports included), but the message says it is the import's name and to rename the local, and later uses of the name in that function are taken as the local, so the cascading E0085 ("is a module, not a value") is gone.
  - A method that takes `*Self` or `*mut Self` can be called on a temporary, `text.split(s, "=").next()`: the value goes to a hidden local and the method gets its address, as Rust does for method calls. A named value still has to be a `var` for `*mut Self`. `&f()` stays E0035: a pointer that outlives the expression is the case worth a variable.
  - `@testAllocator()` stays limited to `test` blocks (E0075); helpers shared by tests take an `Allocator` parameter. The message already says so.
- **Pointers into a growing `List` or `Pool`** are a trap the compiler does not see: `insert` may move the slots, and the pointer from `get` then reads freed memory (in debug mode `General` holds freed memory back for a while, filled with `0xDD`, so it reads those bytes instead of crashing). The spec's pitfalls and the `Pool.get` line say so. A debug-mode check would need each pointer to carry the allocation's generation, a pointer representation change, so it waits; Handles and indices are the stable names.

## Ergonomics, round 2 (M9.6)

- **Multi-line strings are Zig's `\\` line strings**, not raw backtick or triple-quoted strings. Every line of the literal says it is one, so the lexer decides line by line and Go's newline rule needs one exception (no terminator between two `\\` lines, or before a line starting with `,`, `)`, `]` or `}`, since nothing can follow a line string on its line); a backtick or `"""` string would make the newline rule depend on state carried across lines, and its first and last lines and their indentation are always a question. With `\\` the indentation is outside the text, so `ore fmt` re-indents the lines freely (it works per line and only changes leading spaces), and each token stays on one line. The text is raw (no escapes) and joined with `\n`, without a final newline, as in Zig.
- **An array length is a constant expression** (`[N]T`, `[N * 2]T`, `[css.NPROPS]T`), checked and computed like a global's initializer, so whatever a `let` constant may be built from works, and nothing else does (a local, a `var`, a call, a float or a negative value is E0099). The parser takes any expression between the brackets; a literal stays a literal in the AST. A constant's value is computed the first time a type needs it, even while struct fields are being resolved.
- **Shadowing across the files of a module stays an error**: the files share one namespace (spec §12), and the no-shadowing rule covers every top-level name of the module (spec §6), so a helper `px` in one file of `css/` does block a local `px` in another. What was wrong was the message: "already declared at 1:4" read as a position in the file of the error. A position in another file now carries the file's name (`at css/cascade.ore:1:4`), in every message that points at another declaration.
- **`defer if`**: the deferred statement may be an `if` (with `else`), besides a call, an assignment or a block; `defer { if c { ... } }` was the workaround.
- **A struct's methods stay in its body**, so they cannot be split across the files of a module (no `fn Sheet.parse` outside the struct, unlike Go's methods anywhere in the package). One place lists the whole type, fields and methods, which `ore doc` relies on and which keeps the question "what can a `Sheet` do?" a one-file read; a split would need an extension syntax and a rule for which file's `pub` wins. A large type's code in other files takes it as a `*mut S` parameter.
- **Optional C libraries: `@linkOptional("name")` and `@hasLink("name")`**, not build tags or a `--without` flag. The program says which libraries it can do without, the build finds out whether each one is installed (a framework directory, `pkg-config --exists`, or a trial `clang -lname`), and `@hasLink` is that answer as a build-time `bool`. Both branches of an `if @hasLink(...)` are type-checked everywhere (`ore check` probes nothing), but OIR lowering keeps only the branch that runs (the condition may combine `@hasLink`, `true`, `false` with `!`, `&&`, `||`). Since a dead branch alone does not keep helper functions out of the C file, lowering now also drops every function (and vtable) that `main`, the tests, exported functions and globals cannot reach; the unused `extern fn` prototypes are harmless. `@hasLink` of a library no declaration names is E0100 (a misspelling would otherwise be a silent `false`). A `@link` of the same name wins over `@linkOptional`.

## Ergonomics and runtime, round 3 (M9.7)

- **The root module cannot be imported**, and that stays: every module of a program is loaded because the root imports it, directly or not, so a module that imported the root would always close a cycle, and import cycles are an error (E0083), as in Go. Zig's `@import("root")` works because Zig allows cycles; allowing them here would make the module graph a question of order again. What the root and a module both need goes into a module of its own (`browser/page/`), which both import. `import browser` from a module of the program `browser` (or `import main` for a one-file program `main.ore`) is E0083 with that advice, instead of "cannot find module".

- **`orelse` chains** (`a orelse b orelse c`): when the fallback is a `?T` itself, the result is a `?T` (Zig's rule), and `orelse` stays left-associative, so `(a orelse b) orelse c` reads as written. Making `orelse` right-associative instead would have changed what `x orelse y catch z` means. A fallback `null` also gives the `?T`.
- **`==` on error values** compares the errors, as for enums without payloads; errors are identified by name across sets (section Errors), so `e == Other.NotFound` works whatever `e`'s set. A comparison with an error value that `e`'s set cannot hold is always false and is E0060. `<` and the other orderings do not apply. `match` stays the way to tell several errors apart.
- **`_ = x`** drops a value, as in Zig and Go: `x` is any expression with a value (an error union still needs `try` or `catch`). `_` is not a variable: it cannot be read, and `_ =` takes only `=`.

- **Branching on an error union: `if f() |v| { } else |e| { }`** (Zig's form), not `match` on `E!T`: an `if` already unwraps optionals with `|v|`, so the error union reads the same with an error capture after `else`; a `match` would need a pattern for "the value" next to error patterns. The `else |e|` is required (E0102), since it is what handles the error (an `if` without it would drop errors silently), and it takes a block that may simply end, unlike a `catch` block for a non-`void` payload. `E!void` has no value to capture: `if check() { } else |e| { }`. As for `catch`, the trace entries of an error handled there are dropped when the block ends normally.
- **`return match x { ... }` in an `E!T` function** treats each arm as the operand of a `return`: a `T`, an error value or an `E!T` call, so `return match act { .Back => back(s) ... }` needs no `try` per arm (lowering tests the union and runs `errdefer`s, as for `return f()`). Only a `match` that is returned directly works this way; elsewhere an error union is still handled where it is made.

- **Struct field defaults** (`w: f64 = 100.0`, as in Zig): a struct literal may leave out a field that has one. The default is a constant, checked and computed like a `let` constant's value, in the struct's module (E0103 for a call), so a literal never runs hidden code and every literal of the type gets the same value; the value is checked against the field's type once, also for a field nobody leaves out. A field without a default is still required (E0039), so adding a required field still finds every literal. For a type function's struct, the default is checked for each instance (`items: []T = []T{}` works for any `T`). Enum variant fields have none: a variant literal is the variant's data. `@zeroed(T)` became a constant for this (`flags: [64]bool = @zeroed([64]bool)`, also in a global). The browser's 35-field layout `Box` needed a helper that listed every field.

- **C's integer types are predeclared names for Ore's**: `c_int` is `i32`, `c_long` and `c_longlong` are `i64`, `c_ulong` `u64`, and so on (`c_short`, `c_ushort`, `c_uint`, `c_ulonglong`), the sizes of the LP64 systems that stage0 targets (macOS and Linux). They are the same types, not new ones, so a `c_long` adds to an `i64` without `as`; what they give is a declaration that says what the C header says (`FT_Long`), and the place to change when a target where `long` is 32 bits (Windows) comes. `c_char` is left out: its sign differs between targets, and C strings are `[*]u8`.
- **`extern union`** declares a C union (`SDL_Event`), rather than a size and alignment written by hand and `@ptrCast` to each event's struct. `union` is a keyword only after `extern`, so it stays a usable name. It is an `extern struct` whose fields share their memory: the C union in the generated code, with C's layout. A literal sets exactly one field (E0104), since the others share its bytes; reading another field reinterprets them, as in C (Ore's own tagged unions are enums, whose `match` knows which variant is set). A union has no `==` (which bytes would compare?) and no field defaults; `@zeroed` makes one.

- **Reading lines: `File.reader(alloc)` and `Reader.readLine()`**, a buffered reader (Go's `bufio.Reader`, Zig's `std.io.BufferedReader`) rather than `File.readLine(alloc)`: a `File` is a copyable descriptor, so it cannot keep the bytes read past a line, and reading byte by byte would make a system call per byte. `readLine` returns a slice of the reader's buffer, valid until the next call (no allocation per line), `null` at the end; it reads only when it has no complete line, so an interactive input is answered line by line (the browser's agent servers read one JSON line at a time). The buffer grows to the longest line. `File.read(buf)` is the plain system call. `\r\n` endings lose the `\r`.
- **`std.math.inf()`, `nan()`, `isNan`, `isInf`** are functions, as in Go (`math.Inf(1)`, `math.NaN()`) and Zig (`std.math.inf(f64)`), not constants: a constant's float operations must stay finite (E0089), which catches overflow in constants, and a literal for infinity would need new syntax. `inf` and `nan` come from runtime hooks (`__builtin_inf`); `isNan(x)` is `x != x`.

- **Repeat literal: `[N]T{value, ..}`**, rather than Zig's `[_]T{x} ** N` or a `@splat` builtin: the type states the length once, `..` already means "and the rest" in patterns, and no array operator (`**`) is added. The value is evaluated once and copied into every element (a loop in the generated C; a constant in a global), so `[13]List(u8){List(u8).init(a), ..}` makes 13 empty lists. Exactly one value comes before `..` (E0045), and `[_]` cannot repeat: the length would be unknown.

- **A struct can be an `Allocator`** when it has `fn alloc(self: *mut Self, size: usize, align: usize) ?[*]u8` and `fn free(self: *mut Self, p: [*]u8, size: usize)`; a `*mut S` (`&mut slab`) converts where an `Allocator` is expected, as a `*mut S` converts to `dyn I` (E0105 otherwise). The compiler emits thunks from the runtime's allocator vtable to the two methods, so `create`, `alloc`, `free`, `resize`, `List`, `StrMap` and every other allocating function work with it unchanged. The methods are byte-level, like the vtable (the typed methods stay intrinsics: an interface method cannot take any type), and are found by name, like `dyn` (no `impl`). `free` now gets the size: the runtime's vtable passes the bytes `create` or `alloc` asked for (`destroy` knows the type; `free(s)` uses `s.len` and the element size), so a slab or size-class allocator needs no header. Hence a slice must be freed whole: `std.fs.File.readAll` shrinks its buffer to the bytes read (one copy) instead of returning a shorter view of it. The browser's JavaScript engine has its own slab allocator, which can now be handed to code that allocates.

## Round 4 and design leftovers (M9.8)

- **Checks are emitted inline.** Every overflow, bounds, slice, division, shift, negation and cast check used to be a call of a small `static inline` helper, which clang does not inline at `-O0`, so a debug build of an image decoder ran 4 to 10 times slower than it had to. Now a check is an `if (ORE_UNLIKELY(cond)) ore_panic(...)` before the statement (OIR operands are locals and constants, so the check can read them again), and `a + b` is `if (ORE_UNLIKELY(__builtin_add_overflow(a, b, &dest))) ore_panic(...)` into its destination. The checks keep the statement's `#line`. `always_inline` helpers were measured too: at `-O0` they were slower than the calls (1.73 s against 1.55 s), because inlining at `-O0` copies every argument through memory. A decode-like loop (RGB to gray over 4 MiB, 8 rounds): debug 1.52 s before, 0.54 s after; the same loop without any check at `-O0` takes 0.55 s, and safe mode 0.05 s. The rest of the gap is `-O0` itself; `-Og` would run it in 0.08 s but makes stepping and variables in a debugger less faithful, so debug mode stays at `-O0`. A constant divisor other than 0 and -1, a constant shift amount below the width and a constant index below an array's length need no check.
- **`x is .V`** (keyword `is`) is a `bool`: does the enum value `x` (or the enum a pointer `x` points to) hold variant `V`. It binds nothing: `if x is .V { a, b }` would be a second pattern syntax next to `match`, and the browser's need was the test (`if tok is .Eof`, `while !(n is .Done)`). It has the precedence of the comparisons and does not chain with them. On a value that is not an enum it is E0106, which points error values to `==`.
- **`where T: Integer` gives `T` the integer operators** (arithmetic, wrapping, bitwise, shifts, comparisons, unary `-` and `~`), integer literals of type `T`, and `as` to `T` from any numeric type; before, it allowed only `as` from `T`. The generic is checked once with the abstract `T`, where these are accepted, and each instance again with its integer type, where `-x` on `u8` or `return 300` for `u8` is an error. Such an error is reported in the generic's body and names the instance and where it was made (`(in the instance \`negate(u8)\` made at 12:14)`). With that, `std.math` gets `minOf`, `maxOf`, `absOf` and `clampOf` written once in Ore (`std.math.minOf(i32, a, b)`). The names say "of a type" because the type is the first argument; Zig's `minInt(T)` means the smallest value of `T`, which an AI would confuse with a minimum of two integers. There is no `Float` or `Number` constraint: the float functions stay on `f64`, which every libm function takes, and `f32` converts with `as`.
- **`std.math`** adds libm's `trunc`, `fmod`, `sin`, `cos`, `tan`, `asin`, `acos`, `atan`, `atan2`, `exp`, `log`, `log2`, `log10` and `hypot` as `pub extern fn` (`-lm` is always linked), and `sign` in Ore (-1, 0 or 1; a NaN stays NaN, and -0.0 gives -0.0).
- **Struct keys: `@hash` plus a built-in `where K: Hash`.** `std.map.HashMap(K, V)` needs `==` and a hash on an abstract `K`, and a generic's `T` has no operators. A user-written `Hash` interface would make every key type write a `hash` method (and a struct has no `==` to call from Ore code), so `Hash` is built in like `Integer`: the types that `==` compares satisfy it, and it gives `T` `==` and `@hash`. `@hash(x)` hashes exactly what `==` compares (a struct field by field, an optional by `has` and value, a float by its bits with `-0.0` as `0.0`, an enum by its tag, a pointer by its address), so equal values hash the same; each scalar is mixed in with SplitMix64's finalizer, lowered inline in OIR like `==`. `[]u8` does not hash because `==` does not compare slices (it would be a hidden loop); `StrMap` stays the map for strings.
- **Doc examples are test bodies, not programs.** A ```` ```ore ```` block in a `///` comment becomes `test "doc: name (line N)" { ... }` of its own file when `ore test` runs: it calls the documented function directly (private ones too), uses `try`, `@expectEqual` and `@testAllocator()`, and needs no `main` or imports. As a program of its own it would have to import the module it documents, which a single-file root cannot do. The example's tokens keep their place in the comment, so an error or a failed assertion points at the comment line. Only `ore test` adds them; `ore build`, `run` and `check` are unchanged, and std's examples are left out like std's tests.
- **`@setSafety(false)` covers a whole block and must start it.** Zig's `@setRuntimeSafety` may appear anywhere in its scope and still applies to all of it, which reads as if it applied from that line on; requiring it first (E0108) makes the two readings agree. It is lexical: the block and the blocks in it, not the functions they call, so a hot loop opts out without changing what a helper does elsewhere. `@setSafety(true)` in an inner block brings back the build mode's checks (none in `fast` mode). It removes the checks Ore emits (overflow, bounds, division, shift, cast, `unreachable`, unwrap of null), not the allocator's debug checks. The argument is a literal: a computed safety level would be a check that the reader cannot see. OIR keeps such a block as `Safety { on, body }`, since a block otherwise flattens into its parent.
- **`simd[N]T` is a C vector with lane-wise operators and a separate mask type.** Design said only `simd` has operators on a non-scalar type; the stage0 version is minimal but real: `+ - *`, `/` on float lanes, unary `-`, comparisons, `v[i]`, `@splat`, three reductions, `@all`/`@any` and `@select`, emitted with clang's `vector_size` (aligned at most 16 bytes, which is what allocators guarantee, so a vector inside an allocated struct is never misaligned). A comparison gives `simd[N]bool` (an `int8_t` vector in C) rather than a `bool`, so `if a == b` is an error that points to `@all`/`@any` instead of silently meaning "all lanes". A scalar does not broadcast (`v * 2.0` is an error with a `@splat` hint): an implicit broadcast is an implicit conversion, which Ore has nowhere else. Integer lanes wrap without checks, as SIMD hardware does; integer `/` is left out because it has no vector instruction and division by zero would need a per-lane check. Lane count is limited to 2 to 64, a power of two, as the C extension requires. Reductions and `@select` are lane loops in a C statement expression, which clang vectorizes at `-O2`.
- **`std.diag.Diagnostics` is the error-detail convention.** Errors stay plain values; a function that must say where and what passes `diags: *mut Diagnostics` and returns its error, as design.md asks. A `Diagnostic` is `{code: u32, start, end, message}`: a caller-defined code, a byte range rather than a line and column (the function sees offsets; `lineCol(text, offset)` converts once, for display, which is what the browser's out-parameters did by hand), and a message that `add` copies, so a message built in a `Builder` can be freed right away. `add` can fail (`AllocError`), and the function decides whether to stop at the first problem or collect them all.

## Round 5 (M9.9)

- **A `catch` or `orelse` block ends with its value**: when the payload is not `void`, an expression as the block's last statement is the replacement (`catch |e| { report(e); old }`), as the last expression of a Rust block is its value. Zig needs a labeled block (`catch |e| blk: { ...; break :blk old; }`), and before this Ore needed `var u = old` before an `if f() |v| { u = v } else |e| { ... }`, which cannot be a `let`. Only these two blocks give values: `if` and `match` arms stay statements, so a block in any other place still reads as statements only. The rule is typed, not syntactic: a last expression of type `void` (a call that returns nothing) is a statement, so `{ log() }` is still E0067, whose message now names both ways out; a `match` with block arms and `unreachable` stay statements too. The value is computed before the block's `defer`s run, so it may read what they free. No existing program changes meaning: a block that did not leave was an error.
- **`@downcast(*mut S, d)` is a checked downcast of a `dyn`**, Go's type assertion (`h.(*Script)`) and Rust's `downcast_mut` without `Any`: the `dyn` already carries a vtable per (interface, struct) pair, so comparing it with `S`'s answers the question at no cost and with no type ids. It gives `?*mut S`, so the miss is handled with `orelse` or `if |p|`. A builtin rather than `as`: `as` converts numbers and never fails, and `@downcast` reads like `@ptrCast` next to it while being checked. `*mut S` is allowed only when `S` implements one of the interface's methods with `self: *mut Self`, because only then the `dyn` cannot have come from a read-only `&x`; otherwise `@downcast` gives `*S`. A `?dyn` is unwrapped first, so a `null` result always means "another type". Closures stay out (spec section 4): with the downcast, a table of `fn(*mut Interp, ...)` natives reaches its host's state through the `dyn Host` the engine already has, instead of a second untyped `[*]u8` and an unchecked `@ptrCast`.

## Threads (M10)

- **`std.thread.spawn(T, f, arg)` runs `f(arg)` with `f: fn(*mut T)`**, the same shape as a C thread function, so no closure or boxing is needed: the caller keeps `arg` alive until `join`. A small runtime hook (`ore_thread_spawn`, in the C prelude) carries `f` and `arg` to `pthread_create`; Ore hands it `f` as a `fn([*]u8)`, which needed `@ptrCast` between function types (also useful for C callbacks). `Thread` holds the `pthread_t` as a `u64` (8 bytes on macOS and Linux). Every program is built with `-pthread`.
- **Stack size (M9.7):** `std.thread.spawnWithStack(T, f, arg, stack)` starts a thread with a stack of at least `stack` bytes (rounded up to a multiple of 64 KiB, at least 256 KiB, since macOS wants whole pages), and `spawn` asks for 8 MiB, so a thread gets the main thread's stack on every system (macOS gives other threads 512 KiB by default). Deep recursion runs on such a thread, rather than on a main thread with a bigger stack: a linker flag for the main thread's stack works on macOS (`-stack_size`) but not on Linux, where `ulimit -s` decides, and a build option that moved `main` onto a thread would change what `main` is. The browser's JavaScript engine had started a 1 GiB pthread itself, through `extern fn`s and `@ptrCast`.
- **Stack overflow panics (M9.7)** in debug and safe mode: `main` installs a `SIGSEGV`/`SIGBUS` handler that runs on an alternate signal stack (each thread gets its own, 128 KiB), and each thread records the top of its stack and its size (the main thread's from `getrlimit`, 8 MiB when unlimited; a spawned thread's from `spawnWithStack`). A fault within 1 MiB of the end of the stack flushes stdout and writes `panic: stack overflow (deep recursion: run it on a thread with a larger stack, std.thread.spawnWithStack)`, then aborts (status 134, like a panic); any other fault restores the default action and crashes as before. There is no position: the handler cannot know which call overflowed without unwinding. The `sigaction`, `stack_t` and `siginfo_t` layouts are written out for macOS and Linux, as the prelude includes no libc headers. A check in every function's prologue was the alternative; it costs every call, and the guard page already catches the overflow. `fast` mode installs nothing.
- **`Mutex` and the condition variables of `Channel` live on the C heap**, created by runtime hooks, and the Ore value is a handle: a `pthread_mutex_t` must not move once used and its size differs between systems, while Ore copies structs freely. `deinit` frees it; the memory is not counted by `General`'s leak report.
- **`Channel(T)`** is written in Ore: a ring buffer of `?T` slots (no zero value of an arbitrary `T` is needed), a mutex and two condition variables. `send` waits while full and fails with `ChannelError.Closed` after `close` (an error, not a panic as in Go); `recv` waits while empty and gives `null` once closed and drained, so `while ch.recv() |v| { }` is the consumer loop.
- **Atomics are builtins** (`@atomicLoad`, `@atomicStore`, `@atomicAdd`, `@atomicSub`, `@atomicCas`) that cgen emits as C11 `__atomic` builtins, sequentially consistent, on a pointer to an integer (E0101 otherwise). A runtime hook per integer type would not work from a generic `Atomic(T)`; builtins type-check against `where T: Integer` like `as`. `std.sync.Atomic(T)` wraps them. Weaker orderings wait for a use.
- **What is not thread-safe:** the allocators (`General`'s debug bookkeeping, `Arena`) are not locked; each thread gets its own, or allocates nothing (a channel's buffer is allocated before the threads start). The error return trace is thread-local. There is no data-race checking in the language; `--cflags -fsanitize=thread` builds with ThreadSanitizer, and the golden tests run the fan-out program under it where clang's ThreadSanitizer works (it is skipped otherwise: on the development machine (Darwin 25, Apple clang 17) every `-fsanitize=thread` program crashes at start-up, so the run there was not verified).
- **`--cflags "flags"`** (build, run, test) passes more flags to clang, rather than an environment variable: the build is reproducible from its command line.
