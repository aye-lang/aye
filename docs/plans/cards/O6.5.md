# O6.5: `std.crypto` SHA-384, SHA-512 and HMAC over them

- lane: aye
- goal: `std.crypto` has SHA-384 and SHA-512 and HMAC-SHA-384 and HMAC-SHA-512 in the shape of SHA-256: a streaming struct (`init`, `update`, `final`), a one-shot function, `[48]u8` / `[64]u8` results, `///` docs.
- serves: Dweller card Q3.7b (CSP `sha384-` / `sha512-` source hashes). Std had only SHA-256, so Dweller wrote its own in `browser/csp/sha512.aye`, `sha512-block.aye`, `sha512-constants.aye`. Dweller's rule is "std first".
- cause: O3.3 stopped at SHA-256, SHA-1 and HMAC-SHA-256 (the cards then needed nothing wider).
- choice:
  - `Sha512` is the SHA-256 struct with `u64` words, 128-byte blocks, an 80-round schedule, a 256-byte buffer and a 128-bit length (`pad128`; the high 64 bits are `total >> 61`, so it is right for any `u64` length). `K512` and the two initial states are FIPS 180-4 constants (taken from Dweller's file, checked against the vectors).
  - `Sha384` wraps a `Sha512` started from the SHA-384 initial words and cuts the digest to 48 bytes: one block function for both.
  - `HmacSha512` / `HmacSha384` mirror `HmacSha256` with a 128-byte block (a key over 128 bytes is hashed first). Truncation to fewer bytes is the caller's (`d[..16]`), as for SHA-256.
  - New pub names: `Sha384`, `Sha512`, `sha384`, `sha512`, `HmacSha384`, `HmacSha512`, `hmacSha384`, `hmacSha512`. No change to existing ones; no compiler change.
  - Pure Aye, no extern: wherever SHA-256 compiles, these do.
- files: `std/crypto/crypto.aye`, `tests/tests/std_crypto_sha2_wide.aye` + `.out` (new; test blocks), `tests/conformance/crypto/{sha512,sha384,hmac_sha2_wide}.aye` + `.out` (new), `docs/spec.md` (std module table), `CHANGELOG.md`
