# O7.8: `--coverage`: edge counters for fuzzing, read by `std.coverage`

- lane: aye
- goal: `aye build|run|test --coverage` makes clang instrument the Aye code with sanitizer-coverage edge counters, and the new `std.coverage` reads them as a `[]u8`, so a fuzzer written in Aye can keep the inputs that reach new code.
- serves: O7 (the gate), from Dweller Q1.10a2 ("the HTML target's corpus grows from new edges"); Dweller's `dweller fuzz TARGET` (`browser/fuzz/fuzz-loop.aye`, driven by `browser/tools/fuzz.py`) mutates blind today
- id: O7.7 is the name of another branch in flight, so this card takes O7.8.
- cause: clang has the instrumentation (`-fsanitize-coverage`), but nothing in Aye asked for it nor received its callbacks: the runtime had no `__sanitizer_cov_*` function (a link error with the flag) and std no way to read the counters.
- choice:
  - Cheapest sound approach: `inline-8bit-counters` with `edge` (one byte per CFG edge, incremented inline, no call per edge), not `trace-pc-guard` (a call per edge) and not `pc-table` (not needed to count; `__sanitizer_cov_pcs_init` is then not required). `pc-table` is what maps an edge to a function and line; it can be added for a report tool (left).
  - The flags are added by the driver (`COVERAGE_FLAGS` in `src/driver.rs`: `-fsanitize-coverage=edge,inline-8bit-counters -DAYE_COVERAGE`) when `CProgram::coverage` is set (`--coverage` of `build`, `run`, `test`; `run_tests` gets a `coverage` parameter). The generated C is the same with or without the flag; only `-DAYE_COVERAGE` differs, so without it the runtime has no callback, no state and no instrumentation (`std.coverage` links to three one-line stubs that return 0 and are dropped when unused, as the other `AYE_RT` functions are).
  - Runtime (`src/cgen.rs`, next to `std.os`): `__sanitizer_cov_8bit_counters_init(start, stop)` (defined in unit 0 of a split build only) records up to 8 regions in `AYE_DATA` globals, joining ranges that overlap or touch. clang calls it from a constructor of every object, and the linker has merged the units' counters into one section, so every unit reports the same range: one region on Linux (tried with `ld` on a 3-unit C test and with the split build of Dweller). A toolchain that keeps them apart gives `regions() > 1`; `edgeCount`, `setCount` and `reset` cover all regions, `counters()` is region 0.
  - `AYE_RT` (the C runtime of the prelude) is `no_sanitize("coverage")` under `-DAYE_COVERAGE`, so the counters are the program's, its dependencies' and the Aye std's, and the allocators, `std.fs`'s helpers and the like do not add noise. libc and the `@link` libraries (libcurl, SDL) are not compiled by us and not instrumented.
  - `std.coverage` (`std/coverage/coverage.aye`): `enabled`, `regions`, `region(i)`, `counters`, `edgeCount`, `setCount`, `reset`. Without the flag the module still compiles (a std module that fails to compile in half the builds is worse for a fuzzer that is also a normal binary): `enabled()` is false, every region is empty, every count 0.
  - The slice is read-only for the caller (`[]u8`; `[*]mut u8` is not a type); `reset` clears it through `memset`.
  - wasm targets: the flag is accepted and does nothing (no instrumentation, `-DAYE_COVERAGE` unset).
  - Counters are after clang's optimizations: `debug` has one per branch; at -O2 a branch clang turns into a select has none, and an inlined function has counters per caller. A fuzz build should use `--mode debug` or `safe` and know this. Documented in `docs/cli.md`.

- left:
  - Dweller Q1.10a2 (not done here): `fuzz-loop.aye` would call `coverage.reset()` before each input, run it, read `coverage.counters()`, merge into a `seen` bitmap (a `[]u8` of the same length, `seen[i] |= bucket(counters[i])`), and add the input to the corpus when the merge sets a bit; build the fuzz binary with `--coverage` (`browser/build.sh` has no flag for it) and in a mode where branches stay branches.
  - `pc-table` (`__sanitizer_cov_pcs_init`) to turn an edge index into a function and line; `trace-cmp` (`-fsanitize-coverage=trace-cmp`) for comparison-guided mutation.
  - Not tested on macOS (the flags are the same in Apple's clang; the section name differs and the linker merges it too).
  - Thread safety: the counters are plain bytes; two threads lose increments, which does not matter for "was it hit", and `reset` while another thread runs loses nothing but accuracy.
