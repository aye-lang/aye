# O7.9: safe mode's checks stop blocking inlining

- lane: aye
- goal: in an optimized build with checks (`--mode safe`), a hot checked helper is inlined where fast mode inlines it, with the parallel unit build kept and no check changed.
- serves: O11–O13 (numbers), from Dweller Q4.24 (`docs/plans/cards/Q4.24.md`, `browser/engine/PERF.md` section Q4.24): in the safe build `vmWide` is a call on every wide operand read (53 M instructions of richards's gap), `vmKeyedDenseElem` is outlined (326 M on navier-stokes), and `Heap.obj`, `vmContextCell`, `vmEnvAt` cost more than in fast.
- cause: not the split. Q4.24 blamed `cgen::Parts::split` and `compile_parts` (without LTO clang inlines within a unit, and only functions of at most `SMALL_FN` = 1024 bytes of C are `static inline` in the shared header). But the split puts `vmWide`, `vmKeyedDenseElem`, `vmContextCell`, `vmEnvAt` and `vmGlobalSlot` in the same unit as `vmLoop`, their only caller (unit 2 of 4, by a parse of `aye emit-c browser --mode safe`), and the one-unit build (`taskset -c 0`: k = 1, every function `static`) inlines none of them more. The cause is clang's inline cost: each check's `aye_panic*` call costs about 25 plus 5 per argument, cold or not. `clang -O2 -Rpass-missed=inline` of the safe C: `vmWide` into `vmLoop` cost 420 against a threshold of 225 (its 6 index and 2 overflow checks are almost all of it), `vmKeyedDenseElem` 400–465, `vmEnvAt` 275, `vmGlobalSlot` 585. Fast mode has no such calls, so it inlines them.
- choice:
  - Safe mode (`checks && !trace` in `cgen::emit`): a failed check jumps to one panic call per kind at the end of its function. `if (AYE_UNLIKELY(c)) AYE_PANIC_INDEX_GO(pos, i, n);` stores the position and values in the function's `aye_p*_` locals (`AYE_PANIC_VARS`, declared in every function) and `goto`s `aye_panic_index_:`, which `AYE_PANIC_INDEX_AT` emits once after the body, only when used (`Gen::joined`); `aye_panic` and `aye_panic_slice` the same. A function that returns nothing gets a `return;` before them. What is checked, the message and its position do not change.
  - Debug mode keeps the call at each check (a debugger stops on the check's line); debug and fast mode generate the same C as before (only the prelude gains the macros).
  - `split` is unchanged: every partitioning option measured worse (below).
  - No `@inline` attribute here: without the jump it is worse; with it, it pays (below), so it is a language step of its own.

  - Dweller: nothing to remove; `vmWide2`/`vmWide4` of Q4.24's prototype A are no longer needed for inlining (`vmWide` is inlined now), only for its checks.
