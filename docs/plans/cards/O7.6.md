# O7.6: small functions inline across the units of a split build

- lane: aye
- goal: in an optimized build split into units, small functions (`List(T).items`, `len`, `append`, `StrMap.get`) can be inlined into callers in every unit, not only the unit that defines them.
- serves: O11–O13 (numbers), from Dweller card Q4.16d ("aye follow-up": `<deduplicated_symbol>` 17–22% of Dweller's self samples on bbc)
- cause: `compile` (`src/driver.rs`) splits a program of 200 or more functions into up to 8 contiguous runs of function bodies (`Parts::split`, `src/cgen.rs`), compiled by separate clangs without LTO. The generic std instances are emitted first and land in unit 0; every caller in units 1–7 calls them out of line (`AYE_FN` is `visibility("hidden")`, not `static`), and ld64 folds the identical copies into `<deduplicated_symbol>`. Repro: 250 functions `g0`..`g249` plus `fn hot(l: *List(u32), i: usize) u32 { return l.items()[i] }`; `aye build --mode safe`, `otool -tV -p _aye_f_hot` shows `bl _aye_m_..._List_28u32_29_items`.
- choice: (b), `static inline` in the header. In safe and fast builds `Parts::split` moves every function whose C is at most `SMALL_FN` = 1024 bytes (`src/driver.rs`) out of the units to the end of the header as `static inline` (its prototype too), each with its `#line`; debug builds pass 0 and are unchanged. Function values cannot be compared in Aye (E0025), so a copy per unit changes no behavior.
- numbers (M2 Pro, `scripts/capped.sh`, Dweller origin/main ed72da5e, `browser/build.sh` = safe; base = aye origin/main dc9d164; the machine was loaded by other agents, 1-minute load 8–11, so build times are above the 8–12 s of an idle machine):

  | | base | (a) ThinLTO | (b) static inline |
  |---|---|---|---|
  | jsbench geometric mean speedup (`BENCH_BASELINE=base BENCH_REF=none`, median of 3, interleaved) | 1 | 1.181 | 1.179, 1.128 (second run, `dom` 0.77) |
  | `browser/build.sh` wall, same rounds | 12.2, 30.2 s | 56.0, 61.6 s | 40.0, 37.1 s |
  | build wall, 3 interleaved rounds (final code) | 29.9 / 29.5 / 31.0 s | | 33.1 / 34.2 / 34.3 s (+12%) |
  | binary / `__TEXT` | 7.28 MB / 4.67 MB | 6.33 MB / 5.47 MB | 7.48 MB / 4.75 MB (+2.8% / +1.8%) |
  | `nm` `*_items` / `List*_len` symbols | 175 / 137 | 45 / – | 43 / 0 |

  (a) gives the same speedup at about twice the build time of (b), needs an LTO linker on Linux (lld or the gold plugin; the release and install workflows install only `clang`) and `-object_path_lto` for the dSYMs of safe builds on macOS. (b) is plain C that any clang compiles.
- files: `src/cgen.rs` (`Parts::split` takes `small`; unit tests `split_defines_small_functions_inline_in_the_header`, `split_without_small_keeps_every_function_in_a_unit`), `src/driver.rs` (`SMALL_FN`, `compile`)
- verify:
  - `cargo test --release --lib`: 57 passed.
  - repro: `_aye_f_hot` has no call to `items` in safe and fast builds; debug keeps the call (unchanged); output 31132 in all three.
  - Dweller with the new aye: `cargo test --release --test browser -- js_conformance aye_unit_tests`: 2 passed.
  - reproducible: two safe or fast builds of the repro differ in bytes with the base aye as with the new one (temp file names `aye-<pid>-<n>` and the Mach-O UUID); no new source of difference: the header and units are a pure function of the C and `small`.
- status: done 2026-11-08
