# O2.9: std opens descriptors close-on-exec; `Stat` has uid, gid and mode

- lane: aye
- goal: every descriptor std opens is close-on-exec on macOS and Linux, as in Rust's std and Go, so a spawned program inherits only its 0, 1 and 2; `std.fs.Stat` gives the owner (`uid`, `gid`) and `mode` (`st_mode`: permission and type bits).
- serves: O2 (targets), from Dweller cards Q2.5 (patched its own opens), Q2.4c (a renderer inherited files) and Q3.12 (agent socket dir must be 0700 and owned by the user; `browser/ui/owner-mode-of.aye` reads the runtime's internal `aye_std_statbuf`)
- cause: `aye_std_open` / `aye_std_create` (`src/cgen.rs`) passed `O_RDONLY` and `O_WRONLY | O_CREAT | O_TRUNC` without `O_CLOEXEC`; `std.net` made its sockets with plain `socket` and `accept`. `std.process.spawn` pipes were already close-on-exec, but by `fcntl` after `pipe`. `opendir` is close-on-exec in both libcs. `Stat` had only `size`, `mtime`, `kind`.
- choice:
  - `AYE_O_RDONLY` / `AYE_O_CREATE` include `O_CLOEXEC` (macOS 0x01000000, Linux 02000000); wasm32-wasip1 is unchanged (no exec).
  - `std.net`: `newSocket` (Linux `SOCK_CLOEXEC`; macOS has none, so `fcntl(F_SETFD, FD_CLOEXEC)` right after) for `listen`, `listenShared`, `Listener.again`, `connect`, `connectTimeout`; `acceptCloexec` (Linux `accept4(SOCK_CLOEXEC)`, macOS `accept` then `FD_CLOEXEC`).
  - `aye_std_spawn`: `aye_cloexec_pipe`, `pipe2(O_CLOEXEC)` on Linux (atomic against a spawn on another thread), `pipe` + `fcntl` elsewhere. The child's 0, 1, 2 come from `dup2`, which clears the flag on the target, so spawn is unchanged.
  - No opt-out flag: no caller needs inheritance. Aye's own callers (`framework/dev`, `framework/gen`, `framework/build`) pass nothing but 0, 1, 2 to a child; Dweller passes fds to its renderer through its own `socketpair` and spawn, not through std.
  - `Stat.uid`, `Stat.gid`, `Stat.mode` (all `u32`): statx offsets 20, 24, 28 on Linux; `struct stat64` 16, 20, 4 on macOS; wasi-libc 28, 32, 24. Documented in `docs/spec.md` (std.fs) and the `Stat` doc comment.
- files: `src/cgen.rs`, `std/fs/fs.aye`, `std/net/net.aye`, `docs/spec.md`, `tests/cases/std_fs_cloexec_mode.aye` (new), `tests/cases/std_fs_cloexec_mode.out` (new)
- verify (M2 Pro, `scripts/capped.sh`):
  - new golden `std_fs_cloexec_mode`: a shell spawned by `std.process` cannot read (`(true <&N)`) the fd of `std.fs.create`, `std.fs.open` or `std.net.listen` ("closed"), and can read a `dup` of the file ("open", the control); a file chmod-ed to 0600 has `mode & 0o7777 == 0o600`, the regular-file type bits, `uid == getuid()`, the directory's gid. Skipped on wasm32-wasip1 (imports `std.process`).
  - `aye run --mode debug|safe|fast` of the 21 `tests/cases` that use std.fs, std.net, std.http or std.process match their `.out`; `aye test` of `tests/tests/std_{http_decode,http_client,process,net}.aye` pass.
  - `cargo test --release --lib --test spec --test pipe`: 57, 2, 10 passed.
  - `cargo test --release --test framework` (dev server, gen, build spawn children): 24 passed.
  - `aye build -c --target x86_64-linux` of the new case: compiles; the object references `open`, `pipe2`, `socket`.
